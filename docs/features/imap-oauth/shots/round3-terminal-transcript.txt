===== WHAT CHANGED =====

F01  The credentials file's authorize_url carries a policy parameter of its own
     (?p=B2C_1_signin), the way an Azure AD B2C endpoint does. Before: the
     consent URL Redmine built dropped it silently, and the provider's log
     confirms it never arrived - so the provider would answer with its own
     opaque error and nothing in Redmine's output would point at the cause.
     After: p=B2C_1_signin is the first parameter of the consent URL and the
     provider logged receiving it. The grant's own parameters still follow it
     and still win, which is what the two new unit tests pin.

F04  The token endpoint answers 200 with a body that is valid JSON but not an
     object ([]), which is what BADJSON=1 in token_endpoint.rb now does.
     Before: TypeError: no implicit conversion of String into Integer - the
     JSON::ParserError rescue never fires, because the parse succeeded, and the
     hash lookup under it is what breaks. The message names neither OAuth nor
     the endpoint. After: "OAuth 2.0 token request returned no access token",
     the same message every other malformed answer already produced.

control  Unchanged on both sides, and that is the point: the mailbox accepted
     the XOAUTH2 credential over a real socket in both runs, so neither fix
     touched the path that actually fetches mail. The IMAP server logged the
     AUTHENTICATE XOAUTH2 command and closed with authenticated=true either way.
