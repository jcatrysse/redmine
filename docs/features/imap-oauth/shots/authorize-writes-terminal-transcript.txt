G9 for K-26 option B (2026-10-21): redmine:email:oauth2_authorize writes the
refresh token into the credentials file. Driver
verify-harness/g9-authorize-writes.sh. The real interactive task runs as the
unprivileged user `redmine`; the consent URL it prints is followed with curl the
way a browser follows it (the harness's authorize endpoint stands in for the
consent screen and redirects with code and state), and that address is pasted
back on the task's stdin. The token endpoint's log is the witness for whether a
code was exchanged at all. Tokens are fake; that is why the line is shown.

Cases:
  1  first authorization, file without a refresh_token line (the normal case)
  2  directory not writable by redmine
  3  directory made read-only after the consent URL was printed, so the write
     after the exchange fails
